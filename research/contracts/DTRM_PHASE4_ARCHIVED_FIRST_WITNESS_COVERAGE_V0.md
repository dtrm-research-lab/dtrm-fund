## Explicit computation protocol

1. Identify each archived positive representation by the exact tuple `(fmpArticleId, textSha256, ticker)` **in private memory only**. For each capture, union the selected 2d and 5d candidate outputs (maximum 500 items per window). No inference from an absence, even when a 2d output does not hit its cap.
2. Group captures by **exact full familyManifestSha256**. Family transitions always reset state, even if the same tuple may recur across incompatible generations. Within each family, sort captures by GitHub artifact-created UTC time (validate strict order and equality to public metadata), not nominal market `asOf`.
3. For each capture `i`, calculate `positive_representations_in_capture`, `first_witness_within_family` = current set minus union of previously captured positive sets in that same family, `repeat_witness_within_family` = current set intersection previous positive set, `cumulative_distinct_family_witnesses`, `capped_2d/5d`, and `elapsed_days_since_first_family_artifact`. These are **first documented representation** in the archive sample, NOT first creation, provider availability or historical source new links.
4. Summarize by family 4/8/9 snapshots; report total family-specific distinct and cross-family **sum (with possible duplicates)**, independent global union and any differences, and marginal repeat/first appearances aggregated. Do not equate repeats with independent examples.
5. Evaluate **hypothetical strict historical cutoffs** fixed ahead: 2026-09-19T00:00:00Z, 2026-10-01T00:00:00Z, 2026-10-10T00:00:00Z, 2026-10-15T00:00:00Z. At each, include only archived captures with `artifact_created_at < cutoff`, summarize per-family distinct positives and captured appearances (no cross-family semantic merger). Never backdate source possession to market asOf/provider date.
